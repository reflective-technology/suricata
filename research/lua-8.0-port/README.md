# http_custom.lua on Suricata 8.0: port and 7.x parity check

Research for the 7.x → 8.0 upgrade: can the 7.x Lua output (syslog message
format) run on Suricata 8.0 unchanged, and does 8.0's Rust libhtp produce the
same HTTP fields?

## Findings (2026-11-27)

- **The 7.x `http_custom.lua` does not run on 8.0.7.** All 15 Suricata functions it
  calls (`HttpGet*`, `SCFlowTuple`, `SCFlowTimestamps`, `SCPacketTimeString`) are
  gone in 8.0, and the image has no luasocket or lua-json. Suricata keeps running,
  exits 0 and reports the script error only at `Info` level, so the output silently
  stops.
- **`http_custom_8.0.lua`** is the 7.x script ported to the `suricata.http`,
  `suricata.flow` and `suricata.packet` libraries: same 39 fields in the same order,
  same redaction (`REDACT_SENSITIVE_HEADERS`), same raw-capture fragment
  (`ENABLE_RAW_CAPTURE`, JSON escaped byte for byte as lua-json), no external modules.
  It writes to a file (`HTTP_CUSTOM_LOG`, default `/var/log/suricata/http_custom.log`);
  shipping that file (syslog, Kafka) needs a separate reader.
- **Parity, 7.0.16 vs 8.0.7, same config, single thread:**

  | pcap | tx | fields differing |
  |---|---|---|
  | `tests/target` GET + POST | 3 | 0 (also equal to the 7.x fixtures in `http.log`) |
  | depth-regression `traffic-{2mb,11mb,15mb,multipost,60post}` | 85 | 0 |
  | `edge.pcap` (below) | 5 | 1 |

  With `RAW_CAPTURE=true` the raw fragment is byte-identical as well, except on that
  same transaction.
- **The one difference** is the documented 8.0 change: `GET /a b HTTP/1.1` gives
  `uri_path="/a"` on 7.x and `"/a b"` on 8.0.
- 93 transactions is a small sample; a capture of production traffic is the next
  corpus to run.

Not measured: CPU cost of the Lua output on the packet threads, and its behaviour
under production traffic.

## edge.pcap

Generated by `make_pcap.py` (scapy), one TCP connection per case:

1. `Authorization`, `Cookie`, `Set-Cookie` (redaction), `X-Client-IP`, `X-Real-IP`,
   and the other optional request / response headers
2. a space inside the URI
3. POST with a body, a token in the query string, `X-Forwarded-For` twice
4. chunked response; a `"` and a tab in a header value
5. HTTP/1.0, lower-case header names, no space after the colon

## Running

Needs Docker and python3.

```bash
./run-comparison.sh                                   # edge.pcap
./run-comparison.sh ../../tests/target/*/capture.pcap
RAW_CAPTURE=true ./run-comparison.sh edge.pcap
```

The depth-regression pcaps are in `tests/depth-regression/pcap.zip` on
`test/stream-depth-regression`:

```bash
git show origin/test/stream-depth-regression:tests/depth-regression/pcap.zip > /tmp/pcap.zip
```

| var | default | purpose |
|---|---|---|
| `IMAGE_7` | `public.ecr.aws/zuin/cybereyes/suricata:7.0.19` | 7.x side |
| `IMAGE_8` | `public.ecr.aws/zuin/cybereyes/suricata:8.0.7-rc8` | 8.0 side |
| `V7_REF` | `origin/main` | git ref of the 7.x `configs/http_custom.lua` |
| `RAW_CAPTURE` | `false` | sets `ENABLE_RAW_CAPTURE` on both sides |
| `OUT` | `./results` | per-side output and console logs |

Both sides use `compare.yaml` (HTTP only, body limits 100 kb, `stream.reassembly.depth: 0`).
The 7.x script gets `v7-file-output.lua` appended, which only replaces the syslog
transport with a file write. `compare.py` splits each line on the 7.x key order,
because values are not quote-escaped (an ETag holds quotes).

## Files

| File | Purpose |
|---|---|
| `http_custom_8.0.lua` | the 8.0 port |
| `v7-file-output.lua` | appended to the 7.x script: file output instead of TCP syslog |
